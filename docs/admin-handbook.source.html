Part 1

Signing in

The console lives at https://www.divanextechnologies.com/admin.

  1. Enter your email address and password.
  2. A six-digit code is emailed to you. Enter it on the next screen.
  3. The code is single-use and expires. If it does not arrive within a minute, check spam, then request a new one.

Every screen has its own address, so a link can be shared or bookmarked. Add ?tab= and the screen name:

ScreenAddress
Page Content/admin?tab=pages
Page Sections/admin?tab=sections
Blog CMS Studio/admin?tab=blog
Portfolio & Cases/admin?tab=portfolio
Services Catalog/admin?tab=services
Header & Footer Menus/admin?tab=navigation
Search & Metadata/admin?tab=seo
Admins & Roles/admin?tab=users
Audit Trail/admin?tab=audit
A bookmarked link is not a way around your role. Opening the address of a screen your role does not cover shows a short notice instead, and the data behind it is refused separately by the server.
Part 2

The four roles

Every admin account holds exactly one role. Only an Owner can add an admin or change anyone's role — including their own.

In screen counts: Owner and Manager see all 24; Editor and Viewer see 17. The seven hidden from them are Search & Metadata; Backup, Audit & Search; Cache & Performance; Audit Telemetry; Audit Trail; Admins & Roles; and System Settings.

A Viewer sees the screens but cannot save. This is on purpose. Someone can be shown exactly what is on the site and be walked through it without any risk of a change.

Every change is recorded

The Audit Trail stores who made each change, when, from which address, and the value before and after for each field. It also records refusals — an attempt to reach something out of reach is logged too. Passwords, tokens and codes are never written into it.

Part 3

The one rule to remember before you edit

Saving publishes. There is no draft step. The moment you press Save on a content screen, the change is on the live website. There is no preview, no second button, and no approval. Write the text somewhere else first if you are not sure of it.

Two exceptions, both of which do have a held-back state:

  • Blog posts carry a status. A post set to draft is not published and does not appear in the sitemap.
  • Pages can be set to noindex under Search & Metadata. The page still exists and anyone with the link can read it; it is only kept out of search results.

Undoing a mistake

There is no one-click revert. What you do have:

  • The Audit Trail shows the previous value of the field, so it can be typed back in.
  • Backup, Audit & Search takes a copy of every content record. Take one before any large edit — that is what it is for.

Deleting

Deleting a page, service or case study makes its address return Not Found. Anything already linking to it — a menu item, a line in another page, a result in Google — breaks. The console asks you to confirm; read the address in the confirmation before agreeing.

Part 5

How to do the jobs that come up most

Change wording already on a page

  1. Is it in the top block of the page — badge, big heading, the two buttons, the four tiles? Use Page Content.
  2. Anything further down the page? Use Page Sections, then pick the page.
  3. Is it in the header, the footer, or on every page? Use Site Content & CMS or Header & Footer Menus.
  4. Edit, Save, then open the live page and confirm.

Add a service

  1. Services Catalog → Add service. Give it a name and an address (lowercase, hyphens, no spaces).
  2. Fill in the summary, features, use cases, technologies and FAQs.
  3. The page goes live at /services/your-address.
  4. Give it a search title and description under Search & Metadata, or it inherits the site default.
  5. Add it to a menu under Header & Footer Menus if people should be able to find it.

Add a case study

A portfolio card and its case study are two separate records. Adding a project creates the card only. Until the write-up exists the card shows with no link, because a link would open a page that does not exist. The Portfolio screen lists the projects still waiting on one.
  1. Portfolio & Cases → add the project. Note the id it is given.
  2. Open the case study pages editor and add a page using that same id as the address.
  3. Write the overview, the challenge, the solution, the outcome.
  4. Reload the portfolio page — the card now links to it.

Only publish an outcome or a client name you can stand behind. A figure on a case study is a claim the company is making.

Publish a blog post

  1. Blog CMS Studio → new article.
  2. Write it with the status left on draft — a draft is not public and is kept out of the sitemap, so you can work over several sittings.
  3. Fill in the excerpt, cover image, author, category and tags.
  4. Link to at least one service page from inside the article.
  5. Set the status to published when it is ready.

Change how a page appears in Google

  1. Search & Metadata, then pick the page.
  2. Title: aim for under 60 characters. Description: under 160.
  3. Noindex keeps the page out of search while leaving it reachable by anyone with the link.
  4. Google re-reads pages on its own schedule. A change here is live immediately; the search result catches up later.

Point analytics at a different property

Search & Metadata → Google Analytics measurement ID. Paste the G- value from the GA4 property. Leaving it empty stops all reporting and removes the tag from the site entirely. The admin console is never counted — those are staff, not visitors.

Part 6

What this console cannot change

These need a developer and a deployment. That is not a shortcoming — it is the line between editing content and changing the application.

Needs codeWhy
A new kind of section or layout Existing section types can be edited, reordered and refilled. A new arrangement has to be built.
Colours, fonts, spacing, the overall design Held in the stylesheet, deliberately, so the site cannot drift out of brand one edit at a time.
A whole new page type For example country or city pages, which do not exist yet.
New integrations Payments, a CRM, a different mail provider.
Login rules, permissions, security Changing these from a web form would defeat them.
Redirecting an old address to a new one Not built yet. See Part 7.
Do not paste HTML or scripts into a content field. Fields take text and simple formatting. Anything else is escaped rather than run — by design, because a content box that executes code is the easiest way into a website.
Part 7

What is not built yet

Listed plainly so nobody goes looking for a button that is not there.

MissingWhat to do instead
Draft and preview for pages Saving publishes. Draft the wording elsewhere, then paste it in. Blog posts are the exception — they have a real draft state.
Rollback The Audit Trail shows the old value; type it back. Take a backup before a large edit.
Media library There is no uploader. Images are referenced by web address, so host the file elsewhere and paste the link.
Redirects Changing or deleting an address breaks the old one. Ask a developer to add a redirect before changing an address that has been shared or indexed.
Location pages None exist. They need both a developer and genuine local detail for each market — the same page with the country name swapped is worse than no page.
Scheduled publishing Publish by hand at the time you want it live.
SEO warnings Nothing flags a duplicate address, an over-long description or a missing image description. Check these yourself for now.
Part 8

Where to look when something is wrong

SymptomFirst thing to check
The edit saved but the site looks unchanged Hard-refresh the page. If it is still stale, use Cache & Performance to clear the cache for that area.
A red banner at the top of the console The database is unreachable. Nothing will save. Stop editing and tell a developer — carrying on risks losing the work.
A screen is missing from the sidebar Your role does not cover it. Check Part 2 and ask an Owner.
Enquiries have stopped arriving Forms & Notifications → Check mail server. It tests the credentials without sending anything. Also check the recipient address on the same screen.
A link on the site leads nowhere Backup, Audit & Search finds links pointing at pages that no longer exist.
Analytics shows nothing Confirm the measurement ID under Search & Metadata, then check Realtime in Google Analytics while loading the site yourself.
Something changed and nobody admits it The Audit Trail has the name, the time and the exact before and after.
